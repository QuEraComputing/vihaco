Component execution, composite metadata, and observation machinery.

The nondefault typed-declarations feature enables experimental typed execution and capability contracts, including derive support. It decouples the Component/Composite markers from HasInstructionSet; Cargo unification selects that contract for the shared runtime package instance. Declaration macros provide complete dialect/component capabilities and typed composite fields. Feature-off execution retains the existing declarations. The two declaration modes require separate Cargo feature graphs.

The nondefault program-image-execution feature implies typed-declarations and adds PopFromStack, PushToStack, typed stack access, and capability- gated message preparation. A #[program] device supplies program access and operand-storage wiring. Composite authors implement Steps and choose effect handling; program execution lives in stdlib.

With typed-declarations, #[dialect] gives public runtime instruction structs syntax parsers. Operand types retain their authored scope. Only immediate marked nongeneric unit/tuple structs belong to a dialect. Differing annotated operands generate a phase parameter defaulting to Runtime. Composite syntax aggregates lower through instruction-owned Lower implementations; unchanged instructions receive identity lowering.

use vihaco_runtime::{dialect, Parse, chumsky::Parser};

#[dialect]
pub mod arithmetic {
    #[instruction]
    pub struct Add(pub i64);

    #[instruction]
    #[pattern = "'stop"]
    pub struct Halt;
}

let source = arithmetic::Add::parser().parse("add -3")
    .into_result().unwrap();
assert_eq!(source, arithmetic::Add(-3));
let runtime = source;
assert_eq!(runtime.0, -3);

The attribute consumes instruction and pattern helpers, preserves module and field visibility, and supplies Clone/Debug/PartialEq without duplicating those authored derives. Named fields, generic or raw leaf names, conditional membership, and generated-name collisions are rejected. Gate the entire module with cfg/cfg_attr. Unannotated pattern bindings use their runtime field’s parser. A binding such as $0:u64 retains that syntax operand type; differing runtime types require explicit lowering. Parser annotations retain ordinary Rust type scope.
