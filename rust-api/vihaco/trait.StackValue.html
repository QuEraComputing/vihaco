Expand description

One copied logical stack value and its storage-representation conversions.

Separates the type a component computes with from the representation used to access program storage. A component can declare operands such as PopFromStack<(i64, f64)> and receive ordinary Rust values, while vihaco_stdlib::ExecutionState decides how to store them. A later optimized cursor can keep a floating-point value in a native cache without changing that component’s messages or effects. This trait is framework plumbing; ordinary component authors do not implement it or any stack access logic.

Conversions describe one logical value and have no stack access. The default readers/writers consume/produce exactly one value through those conversions. Custom items need not have a Word encoding. This trait does not select an output storage bank or require native float insertion to pass through Word.

Booleans decode zero as false and every nonzero word as true. Insertion normalizes them to 0 or 1; no canonical-input validation is performed.

Required Associated Types§

Source

type Storage

The value representation exchanged with the program’s storage machinery.

Built-in integers and booleans use Word; floats use their native types. For example, components compute with bool, while its storage access uses an encoded Word. An f64 stays an f64 at this interface: word-backed storage encodes its bits, while an optimized cursor can retain the native value and avoid conversions between instructions.

“Storage” describes this internal access representation, not a physical memory location, allocation, or bytecode encoding. It lets program storage evolve independently of the component-facing operand/result types. The selected runtime cache bank remains the storage implementation’s concern.
