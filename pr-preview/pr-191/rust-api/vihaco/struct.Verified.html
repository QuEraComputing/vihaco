Struct Verified

Expand description

A module that passed load-time verification.

The only ways to build one are verifying a module (Verified::new, Verified::verify, Verified::verify_with_state) and the explicit escape hatch Verified::assume_verified. Executable images take a Verified module (the stdlib Image::new, and through it Loadable), so a program cannot run without either passing verification or a greppable assume_verified at its construction site.

Verified gives shared access to the module through Deref and get, but no mutable access: changing the module could invalidate the verification. into_inner gives the module back, unverified.

use vihaco_module::module::{FunctionInfo, LocalModule, Signature};
use vihaco_verifier::{
    Flow, OperandStack, Type, TypedSlot, Value, Verified, Verify, stack_effect,
};

#[derive(Debug)]
enum Inst {
    ConstI64,
    Halt,
}

impl<C> Verify<C> for Inst
where
    C: OperandStack + ?Sized,
    C::Slot: TypedSlot,
{
    fn flow(&self) -> Flow {
        match self {
            Inst::Halt => Flow::Halt,
            Inst::ConstI64 => Flow::Next,
        }
    }
    fn verify(&self, cx: &mut C) -> eyre::Result<()> {
        match self {
            Inst::ConstI64 => stack_effect(cx, [], [Type::I64]),
            Inst::Halt => Ok(()),
        }
    }
}

let main = FunctionInfo {
    name: 0,
    signature: Signature { params: vec![], ret: vec![] },
    locals: vec![],
    start_address: 0,
    end_address: 2,
    file: 0,
};
let module: LocalModule<Inst, Value, Type> = LocalModule {
    code: vec![Inst::ConstI64, Inst::Halt],
    functions: vec![main],
    main_function: Some(0),
    ..Default::default()
};
let verified = Verified::new(module)?;
assert_eq!(verified.code.len(), 2);

impl<M> Verified<M>

pub fn assume_verified(module: M) -> Verified<M>

Treat module as verified without checking it.

This is the escape hatch for tests that exercise runtime checks on deliberately ill-typed programs, for modules produced by a trusted toolchain that already verified them, and for module models the standard verifier does not cover (other value or type models, or machines verified through a hand-written context). Running an unverified module is memory-safe, since the runtime still checks heap tags, bounds and signatures, but errors the verifier would reject at load time surface during execution instead.
