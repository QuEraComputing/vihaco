Typed SST parsing built from pattern-derived instruction and type syntax.

A section’s .text is a flat instruction stream, not structured code:

@main:
execution::program::call 0, @helper
execution::program::ret 1
@helper:
execution::program::const_u64 21
execution::program::ret 1

@name: binds a symbol to the address of the next instruction and occupies no slot; @name in an operand refers to a symbol and is resolved through the section’s symbol table during lowering. Layout and indentation carry no meaning. What a symbol is lives in the header: a function is a symbol with a matching declaration in vihaco_module::module::ProgramMetadata, which supplies its signature and locals. Its executable range runs from its symbol to the next function symbol.

ParsedModule::parse_section yields the header, the code stream, and the symbol table. ParsedModule::lower_with_metadata validates them against the metadata, lowers instructions with their Lower<C> implementations, and assembles a module. Its context can use vihaco_module::loader::MetadataLoweringContext directly or wrap it to add consumer capabilities.

With program-image-execution, HeaderDeclarations<D> parses a collection of semicolon-terminated declarations. Consumers apply declarations separately to an application-owned preparation context, then call lower_code_with_metadata with the completed metadata and instruction context. This supports contexts borrowing prepared configuration without moving the metadata during lowering.

Metadata records use #[derive(Parse)] and #[syntax_class(metadata, open = "{", close = "}")] with an optional head. See vihaco-stdlib/examples/loadable.rs for header declarations, metadata validation, and execution using dialect instructions consumed by components. Feature-off consumers retain the separate Resolve bridge.
